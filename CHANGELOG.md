# Changelog

All notable changes to Isoko, by phase of the course project. Dates are those of the merged pull requests.

## Summative: complete pipeline from Git to production (November 2026)

The system now deploys itself. A change merged to `main` is checked, packaged, pushed to a private registry and deployed to a server in a private network.

### Added
- **Modular Terraform** (`terraform/`) with six modules: `network`, `security`, `compute`, `database`, `registry` and `github_oidc`. It creates a VPC with one public and two private subnets, a bastion host, an application server in a private subnet, a managed PostgreSQL database (RDS), a private container registry (ECR), security groups, and an IAM role that GitHub Actions assumes through OIDC.
- **Bastion host** that also works as a NAT instance (low cost) and runs nginx as the public entry point. A managed NAT gateway can be switched on with the variable `create_nat_gateway`.
- **Ansible** for two server types: a `bastion` role (nginx reverse proxy), an updated `security` role (firewall rules per server type) and a new `app` role that logs in to the registry, pulls the image and starts it with Docker Compose. A second play in `site.yml` configures the application server through the bastion.
- **PostgreSQL storage** in the application, with automatic table creation and seeding. The JSON file is still used when no database is configured, which keeps local runs and tests simple.
- **`/ready` endpoint** and request logging, so an operator can tell whether the service and its database are healthy.
- **CD pipeline** (`.github/workflows/cd.yml`) that runs on every merge to `main`: all CI checks, then build, scan and push of the image, then a deployment with Ansible. SSH to the bastion is opened for the runner only during the deployment.
- PostgreSQL service in the CI test job, so the database code is tested for real.
- Terraform is now validated module by module in CI.
- `CHANGELOG.md`, architecture diagram and operations manual in the README.

### Changed
- The flat Terraform files from Formative 3 (`network.tf`, `security.tf`, `compute.tf`, `outputs.tf`) were split into modules. The single public server became a bastion plus a private application server.
- `requirements.txt` gained the PostgreSQL driver.
- The Ansible inventory is now `inventory/hosts.yml` and reads addresses from environment variables.

### Security
- The database is in private subnets, encrypted, only reachable from the application server, and requires SSL.
- The database password is generated by Terraform and stored in AWS Secrets Manager. It is never committed.
- The pipeline logs in to AWS with short-lived credentials (OIDC). No AWS keys are stored in GitHub.
- The image is scanned for HIGH and CRITICAL vulnerabilities before it is pushed.

## Formative 3: Infrastructure as code and DevSecOps (7 to 13 November 2026)

### Added
- Terraform for AWS: a VPC, a public subnet, a security group, one EC2 server and an Elastic IP.
- Ansible roles `docker`, `app` and `security`, run twice against a real server. The second run changed nothing.
- CI jobs for security: `dependency-scan` (pip-audit), `image-scan` (Trivy) and `iac-scan` (Checkov), plus `terraform-validate` and `ansible-check`.
- `SECURITY.md` with the findings of the scans and the accepted risks, and the AI Use Annex.
- Real run on AWS with evidence, followed by `terraform destroy`.

### Changed
- Branch protection on `main` now requires all eight CI jobs.

### Fixed
- 14 vulnerable entries in Starlette (upgrade of FastAPI and Uvicorn), two HIGH vulnerabilities in the Docker image (operating system updates in the Dockerfile) and nine failed Terraform rules (seven fixed, two documented as accepted).

## Formative 2: Containers and CI (29 to 31 October 2026)

### Added
- A multi-stage `Dockerfile` on a pinned base image, running as a non-root user with a health check.
- `docker-compose.yml` with a network, a volume, a health check and a restart policy.
- `.dockerignore`, `.env.example` and `ruff.toml`.
- GitHub Actions workflow `ci.yml` with lint, test and Docker build jobs, and a smoke test of the running container.
- Branch protection requires the three CI jobs.

### Fixed
- The first CI run failed because the smoke test called the container before the app had started. It now retries.
- A pull request with a deliberately wrong test showed CI failing, and the fix showed it passing.

### Tag
- `f2-submission`

## Formative 1: Foundation (22 to 23 October 2026)

### Added
- Repository with README, MIT license, `.gitignore` and `CODEOWNERS`.
- GitHub Projects board with user stories, labels, milestones and assignees.
- Branch protection on `main`: a pull request, one approval, stale approvals dismissed and conversation resolution.
- The price service in FastAPI: list and filter prices, find the cheapest market, report a price, and pytest tests.
